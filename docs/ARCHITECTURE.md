# 架构说明

## 目标与原则

固定摄像头手机是完整控制器。第二台手持手机只能增加精度或增加输入通道，移除它后原映射仍然可玩。原始视频不离开手机，以降低带宽、延迟和隐私风险。

## 数据路径

```text
固定手机摄像头
  -> MediaPipe Pose + Gesture Recognizer（人体关键点与手势分类，手机本地）
  -> pose_frame_v2 WebSocket（最多两人，只传关键点）
  -> 双人轨迹 + One Euro Filter（自适应低通滤波器）+ 动作状态机
  -> 两套玩家长期校准 + 中文游戏映射
  -> 玩家一键盘 / 两只 XInput（Xbox 输入接口）/ DSU 0、1（模拟器体感协议）

同一手机麦克风
  -> 16kHz 单声道 PCM16
  -> 独立 /ws/audio WebSocket（不与人体帧争队列）
  -> Vosk（离线语音识别）限定中文词表
  -> 每名玩家独立的语音保持状态

可选第二台手持手机（后续）
  -> 陀螺仪 + 加速度计 + 触摸
  -> 同一 WebSocket，role=sensor
  -> 与摄像头动作融合；掉线时自动退回摄像头信号
```

## 职责划分

### 手机端

- 获取相机权限并选前/后摄像头。
- 用 MediaPipe Tasks Vision（端侧视觉任务库）识别最多两人的 33 个身体关键点和最多四只手的分类/关键点。
- 首次对 Lite/Full/Heavy 各测速4秒，选择达到 15 FPS 且推理 P95（95%帧不超过的耗时）不高于60ms的最高精度档。
- 画实时骨架供摆位检查。
- 限制识别频率，网络拥塞时丢弃旧帧而不是堆积延迟。
- 断线自动重连，保持屏幕唤醒。
- 不发送视频像素。
- WASM 推理运行库和人体/手部模型随 Web 包与 Android APK 一起分发，首次识别不依赖外网。

### 电脑端

- 验证帧序列和可见度，用髋部中心、身体比例、运动预测和连续距离维持两条轨迹。
- 轨迹交叉或遮挡造成身份不确定时先归零，绝不交换玩家手柄。
- 用 One Euro Filter（兼顾响应与防抖的滤波器）和准备/触发/冷却/中立状态机处理动作。
- 由个人身体比例、动作幅度和中立位置产生归一化动作信号。
- 保存每次校准会话，再按会话等权、异常值稳健过滤的方式聚合。
- 把布尔动作与连续动作映射到键盘、Xbox 按钮/摇杆/扳机和 DSU 体感。
- 正式玩家 300 ms 没有可靠轨迹时自动归零；超过2秒需要重新站位加入。

## 跨天校准

每个玩家 JSON 档案包含：

- 原始会话列表：日期、每阶段样本数、质量、会话级特征。
- 聚合特征：历史会话的稳健中心值。
- 会话先各自压缩成一份特征，所以 300 帧的新会话不会压过 100 帧的旧会话。
- 质量低于 35% 的会话保留作审计，但不进入聚合。
- 明显偏离历史中位数的值用 MAD（中位绝对偏差，一种抗异常值统计量）过滤。

## 第二台手机预留协议

服务端已经接受 `role=sensor` 的 `sensor_frame`：

```json
{
  "type": "sensor_frame",
  "role": "sensor",
  "device_id": "sensor-uuid",
  "sequence": 1,
  "captured_at_ms": 0,
  "orientation": { "alpha": 0, "beta": 0, "gamma": 0 },
  "acceleration": { "x": 0, "y": 0, "z": 0 },
  "rotation_rate": { "alpha": 0, "beta": 0, "gamma": 0 },
  "touches": []
}
```

第一阶段不会消费这些值，避免摄像头方案尚未稳定时把两个误差源混在一起。
