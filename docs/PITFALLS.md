# 踩坑记录（只追加）

## 2026-08-08：浏览器摄像头安全上下文

局域网 `http://电脑IP` 页面不一定能调用手机摄像头。`getUserMedia`（网页摄像头接口）在主流浏览器要求可信 HTTPS 或 localhost；这不是给 Windows 防火墙放行端口就能解决的问题。开发版保留同源 PWA，正式手机测试优先使用 Capacitor Android 壳，或安装受信任的本地 HTTPS 证书。

## 2026-08-08：跨天校准不能按视频帧直接合并

若把所有历史帧直接求平均，录制时间更长的某一天会不合理地覆盖其他天。当前实现先把每次校准压成会话级特征，再让会话等权进入稳健聚合；低质量会话保留但不参与控制阈值。

## 2026-08-08：Xbox 虚拟手柄需要系统驱动

Python 库本身不能让 Windows 游戏看到 XInput（Xbox 输入接口）设备，还需要 ViGEmBus 内核驱动。因为它是系统级安装且项目已经归档，不在基础设置脚本中静默安装；必须明确安装并用 `joy.cpl` 独立验证。

## 2026-08-08：单目人体姿态不等于手持陀螺仪

身体关键点可以估计躯干滚转、下蹲和移动，但不能在遮挡时重建双手独立的绝对旋转。DSU 输出在第一阶段是“身体运动映射的体感”，不是伪称相机测到了真实 Joy-Con IMU（惯性测量单元）数据。第二台手持手机会作为可选 IMU 增强，掉线时仍退回相机控制。

## 2026-08-08：Gradle 默认下载超时不足

Android 工程生成的 Gradle Wrapper（固定构建工具版本的启动器）默认网络超时为 10 秒，本机连接 `services.gradle.org` 时首次下载直接超时。已将项目级超时调整为 120 秒，并改用同属 Gradle 官方的 `downloads.gradle.org` 二进制分发地址；这只影响构建工具下载，不改变运行时网络延迟阈值。

## 2026-08-08：Capacitor 7 与本机 Java 版本

Capacitor 7 原生库要求 Java 21，而当前可用工具链是 Java 17，首次 Android 编译在 `compileDebugJavaWithJavac` 明确报“无效的源发行版：21”。此应用没有依赖 Capacitor 7 专有 API，因此改用与 Java 17 匹配的 Capacitor 6.2.1，避免为了一个薄壳强制安装另一套系统 JDK。

## 2026-08-09：不能用 npm override 强升 Capacitor 6 的 tar

Capacitor 6 CLI（命令行工具）依赖旧版 `tar` 解包 API，强制覆盖到 `tar` 7 虽能让安全审计归零，却会让 `cap sync` 在 `extract` 方法处崩溃。最终组合为原生运行库 `core/android` 6.2.1（保持 Java 17）和仅在开发机运行的 CLI 7.6.8（使用已修复依赖）。CLI 7 会把两个生成的 Gradle 文件写成 Java 21，因此 `android:sync` 在同步后运行受控脚本，把且只把这两个兼容性字段改回 Java 17；脚本找不到预期字段时会失败，防止静默漂移。

## 2026-08-09：模型走 CDN 会造成假离线

最初的生产包把界面代码打进 APK，但 MediaPipe WASM（浏览器本地运算模块）和模型仍在启动时访问外网，局域网可用却断网时会卡在“首次加载”。现在 `prebuild` 会复制固定 npm 版本的 WASM，并下载后缓存人体/手部模型；缺失或文件异常小时构建直接失败。APK 因此更大，但相机识别不再依赖 CDN。

## 2026-08-09：DSU 验证必须排除旧进程

最终回归时发现 `D:\switch-more\dist\motionbridge.exe` 已占用标准 DSU 端口 26760；向该端口发包收到回复不能证明当前代码成功启动。没有停止这个不属于当前工作区的进程，而是让当前服务如实报告端口占用，再在空闲端口 26761 单独启动当前 `DSUServer` 并完成版本请求/响应验证。以后验收也必须先核对 UDP 端口的拥有进程。

## 2026-08-09：vgamepad 安装脚本会反复拉起旧驱动 MSI

PyPI 的 `vgamepad 0.1.0` 只发布源码包。其 `setup.py` 会全量扫描卸载注册表；只要当前命令不是 `egg_info/sdist` 且没匹配到固定显示名，就同步运行包内 ViGEmBus 1.17 MSI。它不读取网上新版说明提到的 `VGAMEPAD_SKIP_VIGEMBUS_INSTALL` 环境变量。本机其实已有更高的 ViGEmBus 1.21.442 驱动，但仍被误判。最终不再安装该 Python 包，改为内置所需的 MIT 封装等价实现和 64 位 `ViGEmClient.dll`，只连接现有驱动，不执行 MSI。

## 2026-08-09：旧 D 盘进程已按用户授权关闭

用户随后明确允许在需要时关闭旧程序。按完整路径筛选后停止了 `D:\switch-more\dist\motionbridge.exe` 的两个进程，只释放 26760/8765 相关运行状态，没有删除其文件或数据。此后打包版 EXE 在空闲的标准端口上独立完成了 DSU 响应、WebSocket、离线模型和失联归零验证。

## 2026-08-09：浏览器页面地址不能直接当 App WebSocket 地址

电脑最初只显示 `http://IP:8765/phone/`，适合浏览器扫码；Android App 输入框需要 `ws://IP:8765/ws/input`。若简单追加路径会错误变成 `/phone/ws/input`。现在电脑面板分别显示两种地址，App 的规范化函数也会解析协议和主机后强制把路径设为 `/ws/input`，即使用户粘贴浏览器地址也能自动纠正。

## 2026-08-09：MediaPipe 依赖不能使用脱锁的 caret 范围

`@mediapipe/tasks-vision` 原本写成 `^0.10.22-rc.20250304`，npm 因此解析到 0.10.35。该版本包内的 `vision_wasm_internal.wasm` 只有 3,124,117 字节，并且与 11,153,641 字节的模块版文件前缀完全相同；其 WASM 代码段仍声明还需约 9.68 MB，Android WebView（安卓网页运行组件）必然报 `section extends past end of the module`。依赖已锁定为 `0.10.22-rc.20250304`，构建脚本也删除不同包装布局遗留的 module 文件，避免 JS 加载器和 WASM 二进制配错。

## 2026-08-09：手机应用重启会让帧序号归零

手机应用每次进程重启都会从序号 0 开始，而电脑服务会记住同一设备 ID 的上次序号。若电脑服务未重启，新帧会因序号较小被误判为乱序帧。现在只有当旧流静默超过 1.5 秒时才允许较小序号重新建立基线；活跃流里的倒序包和重复包仍会被拒绝，并有单元测试覆盖。

## 2026-08-09：校准不能只在最后检查并清空失败现场

旧流程五段盲倒计时结束后才一次性检查每段是否有 8 帧有效全身画面，任一段不足就进入通用异常处理并立即 `cancel`，导致阶段计数和失败部位一起被清空。现在每段单独验收：记录头部、双肩、双手腕、髋部、双膝和双脚踝的低可见次数，同时检查举手、T 姿、下蹲和双向侧倾的动作幅度。不合格时对话框保留原因和有效帧数，只重采当前段；五段全部通过后才写入长期玩家档案。

## 2026-08-09：校准阶段不是失败重试，而是持续门控

进一步明确交互要求：阶段不合格时不应在倒计时结束后宣布失败，也不应要求用户点击“重新采集”。每个阶段现在持续采集并实时门控（只有当前身体部位完整且动作达到要求的帧才增加进度）；不合格时进度停住并显示下一步调整方法，用户调整正确后自动恢复。第五段通过后才调用最终保存，因此一次流程只要走到结束就必然成功。

## 2026-08-09：无 Git 工作区先做源代码快照

`F:\switch` 没有 `.git`，无法用 `git status` 区分用户已有修改。下一版改造前先把源码、测试、文档、映射和构建脚本（排除 `node_modules`、虚拟环境和产物目录）打成 `build\pre-next-version-source-20260809.zip`，再修改原文件。遇到回归时应从该快照比对，不要凭时间戳猜测。

## 2026-08-09：映射版本2迁移必须先备份再原子替换

旧映射没有版本号、释放阈值和冷却时间。加载时先把所有旧 JSON 原样复制到 `data\backups\mapping-v1-时间戳`，再补齐版本2字段并通过临时文件原子替换。玩家档案和历史校准目录不参与迁移，避免映射升级覆盖身体数据。

## 2026-08-09：语音音频不能和人体帧共用 WebSocket

PCM16（16位脉冲编码音频）是连续字节流，人体关键点是可丢旧帧的 JSON。共用连接会让音频排队阻塞姿态，或因丢帧破坏识别。当前使用独立 `/ws/audio`，并在连接关闭时先释放所有语音保持状态；身体动作继续工作。

## 2026-08-09：算法重放不能使用当前机器单调时钟

动作防抖、冷却如果读取重放当下的 `time.monotonic()`（进程单调时钟），同一关键点文件以不同速度重放会得到不同事件。算法试验台保存手机原始捕获时间和电脑接收相对时间，动作规则使用帧捕获时间推进；A/B（同一输入对比）时两套 `MotionRecognizer`（动作识别器）都直接接收同一 `PoseFrame`（人体关键点帧）序列，不再经过摄像头模型。

## 2026-08-09：影子模式必须在输出路由层硬锁

只在算法测试页面“不调用映射”不够，语音、传感器、看门狗或异常路径仍可能触发已有映射。现在 `OutputRouter`（输出路由器）有独立 `shadow_mode`（影子模式）锁：进入测试先释放键盘、虚拟手柄和 DSU（模拟器体感协议），锁定期间忽略所有启用、按键、摇杆和体感更新，正常结束与异常退出再次释放；测试结束后也不自动恢复输出，必须由用户手动重新启用。

## 2026-08-09：真实试验会话与自动测试样本必须明确分开

自动测试里的骨架只验证格式、重放确定性、统计和输出隔离，不能冒充真人准确率。正式会话默认保存到 `data\algorithm-tests\sessions`，内容来自真实手机的 33 点人体和 21 点手部关键点；格式预留原始视频、PCM16（16位脉冲编码音频）、传感器帧和多人轨迹字段，但 MVP（最小可用版本）不因这些第二阶段数据拖延上线。

## 2026-08-09：Vosk 官方模型服务器适合分段校验下载

中文小模型约42MB，但本机到官方服务器的长连接吞吐低且多次超时。服务器支持 HTTP Range（按字节范围下载），应使用固定区间并行下载，合并后以模型镜像公开的 SHA256 `3af8b0e7e0f835ae9d414ce5df580237a3cfb08d586c9fbbb0f7ff29ad5b14ba` 校验；不能只看 ZIP 文件存在就继续打包。

## 2026-08-09：多人模型选择要按设备和镜头保存

前后镜头的分辨率、曝光和 GPU 路径可能不同，同一手机不应共用一份测速结果。手机端按设备 ID 与镜头方向分别保存 Lite/Full/Heavy（轻量/完整/高精度人体模型）的4秒测速结果，只在 FPS 不低于15且推理 P95 不高于60ms时向上选择；界面保留重新测速按钮。

### 2026-08-09：运行中的单文件 EXE 会让 PyInstaller 假失败变成脚本假成功

- Windows 会锁定正在运行的单文件 EXE（可执行文件）；直接重新生成同名 `dist/MotionBridge.exe` 会触发 `PermissionError: [WinError 5]`。
- PowerShell 默认不会因为外部程序返回非零退出码自动停止，旧脚本随后仍对旧 EXE 计算哈希，造成“构建成功”的假象。
- 发布构建改为 `build/release-pc` 暂存目录，并输出版本化的 `dist/MotionBridge-0.2.0.exe`；所有 `pip` 与 PyInstaller 调用后必须检查 `$LASTEXITCODE`。

## 2026-08-09：Vosk Python 模块能打包不代表原生 DLL 已打包

PyInstaller 能分析到 `vosk` Python 代码，构建日志也可能显示 DLL 搜索目录，但默认不一定把 `libvosk.dll` 及其 GCC（编译器运行库）依赖放入解压后的 `vosk` 目录。结果是 EXE 网页功能正常，只有连接音频 WebSocket 时才报 `_MEI...\vosk` 不存在。规格文件必须显式使用 `collect_dynamic_libs("vosk")`，并以真实 `/ws/audio` 握手验证 `audio_ready`，不能只验证模块导入。

## 2026-08-09：同一 APK 的手持模式不要初始化视觉运行时

手持手柄只需要 SensorManager（安卓传感器管理器）和 WebSocket；如果复用摄像头启动流程，会额外加载 Pose/Gesture/WASM（人体、手势和网页汇编模型），造成明显发热和内存浪费。0.3.0 在角色首页分流：只有“摄像头”角色调用视觉模型，只有“手持手柄”角色注册 Rotation Vector、Gyroscope 和 Linear Acceleration（旋转向量、陀螺仪和线性加速度）。触摸输入必须在抬手、切后台、断线时清空，电脑端仍设置独立的 300ms watchdog（失联保护）。

## 2026-08-09：镜像预览与控制坐标必须分开

手机视频与骨架画布固定使用 CSS `scaleX(-1)` 同步镜像，只影响用户看到的预览；传给电脑的关键点保持原始坐标并明确发送 `coordinates_mirrored=false`。如果把镜像后的坐标也发送，用户向左移动会被游戏解释为向右。

## 2026-08-09：Android 已授权不等于 WebView 音频请求会自动获批

Capacitor 的 WebChromeClient（网页权限桥接器）在处理 `getUserMedia` 麦克风请求时会同时检查 `RECORD_AUDIO` 和 `MODIFY_AUDIO_SETTINGS`。只声明录音权限会出现系统设置显示“已允许”，但网页仍收到 `NotAllowedError` 并误报“麦克风未授权”。清单必须同时声明两项权限，并以真机音频 WebSocket 收到 `audio_ready`、电脑状态显示“语音已开启”为验收结果。

## 2026-08-09：镜像规则更正为仅前置镜头镜像

用户最终确认：后置镜头保持真实画面，前置镜头才做镜像预览；骨架画布必须跟视频使用同一变换，发送给电脑的关键点始终保持原始坐标。荣耀 ELI-AN00 的 Camera2（安卓相机接口）可见7个相机设备，其中包含约1.96mm超广角和8.67mm长焦；但当前 WebView `enumerateDevices()` 只向网页暴露“camera 0, facing back”和“camera 1, facing front”。界面仍按浏览器实际暴露的镜头动态生成选择项；若厂商不暴露物理副摄，不能伪造广角选项，后续需要原生 Camera2 取帧桥接才能直接选择。

## 2026-08-09：Camera2 镜头必须以收到真实帧为可用标准

`CameraManager.cameraIdList`（系统公开相机列表）不一定包含厂商副摄，`physicalCameraIds`（物理镜头编号集合）也可能为空；反过来，能读取 `CameraCharacteristics`（相机特征）也不代表第三方应用能建立捕获会话。原生相机发现流程现在按设备动态读取特征，并对候选镜头实际执行 `openCamera`、创建 YUV 捕获会话和等待真实帧。探测超时从 900ms 调整到 2500ms，避免相机冷启动造成假阴性；只把真正收到帧的镜头标记为可用，其余显示“系统限制不可用”。探测缓存使用设备指纹、系统构建和 APK（安卓安装包）版本组成键，升级或运行时打开失败会重新探测。镜头编号、焦距、尺寸、方向和分辨率均来自运行时，不能写死手机型号或镜头参数。

## 2026-08-09：MediaPipe Android 不能直接接收 Camera2 的 YUV MediaImage

MediaPipe Tasks Vision 0.10.14 的 `MediaImageBuilder`（媒体图像构造器）在当前运行时只接受 `RGBA_8888` 位图，直接传 `YUV_420_888` 会抛出 `UnsupportedOperationException`。RenderScript（安卓并行图像计算组件）在荣耀 ELI-AN00 上又于 `nAllocationCopyToBitmap` 触发原生 SIGSEGV（段错误）。稳定路径改为复用缓冲区的 Java YUV 转 RGBA，不走逐帧 JPEG、Base64 或 JavaScript 桥；720p 继续用于原生预览，独立的 480×270 YUV 输出用于推理，减少转换与模型开销。

## 2026-08-09：MediaPipe 位图包装关闭会回收调用方位图

Tasks Vision 0.10.14 的 `BitmapImageContainer.close()` 会回收传入的 `Bitmap`（安卓位图），复用位图在下一帧调用 `setPixels` 时会报“recycled bitmap”。`detectForVideo`（同步视频推理）返回后只丢弃轻量包装对象，不关闭调用方拥有的复用位图。姿态模型保持逐帧优先，手势模型降低采样频率并在样本间保持上次可靠结果，避免手势推理阻塞人体主循环。

## 2026-08-09：手持模式切后台不能依赖浏览器定时器释放

WebView（安卓网页容器）切后台后会把定时器节流到约每秒一次。如果只清空触摸状态但继续保留 WebSocket（低延迟双向连接），电脑端会在每次低频心跳后短暂误判手持设备重新在线。现在切后台先发送一次归零帧，再停止 60Hz 定时器、关闭连接并停止原生传感器；电脑的 300ms watchdog（失联保护）随后稳定显示未连接、清除居中状态并保持摄像头体感兜底。回到前台后重新连接并要求重新居中。
### 2026-08-13：内部动作模型不能随研究版 EXE 一起分发

OpenMMLab COCO17（17点人体骨架）六分类参数虽然通过 SHA256（文件指纹）、协议哈希和真实前向验证，但初始化权重许可仅允许内部非商业研究。研究试用版只从 `F:\MotionControl` 外部加载参数，绝不复制进 `F:\switch`、APK 或 EXE。普通单文件 EXE 也不能通过修改 `PYTHONPATH`（Python模块搜索路径）可靠加载另一虚拟环境的 PyTorch，因为打包解释器缺少对方完整标准库依赖；最终使用轻量 EXE 启动器调用本机 `.venv-pc`，并把研究环境 site-packages 与 MMAction2 加入搜索路径。任何缺失或校验失败都必须显示“参数准备中”、释放模型动作并回退规则链。

### 2026-08-13：混合控制必须先合成控制意图再输出

动作模型、关键点连续值、区域（触发区）、离线语音和手持手机若各自直接操作 Xbox 控件，会产生重复占用、粘键和预设切换残留。本版统一进入 Input Intent（控制意图）层：支持多源 OR（任一来源）、AND（同时门控）、优先级、互斥、模拟量死区/灵敏度/反向；切游戏、切布局、断线、紧急停止和退出均先显式归零。持久布局用临时文件、`fsync`（强制落盘）和 `os.replace`（原子替换）保存，并在镜头/设备/方向变化时要求重新对齐。

## 2026-08-13：内部研究模型的远端便携包

- 不能把轻量 EXE 启动器当成便携包：它依赖源电脑的项目源码、PyTorch 和 MMAction2，复制到另一台电脑会直接失效。
- ST-GCN++（时空图卷积网络）可完整导出为 ONNX opset 17。本次用 2 个固定输入和 32 个随机有限输入对比 PyTorch/ONNX，最大 logits 绝对误差为 1.5497207641601562e-06，argmax（最高分类别）一致率 100%。
- 模型引擎必须同时校验 ONNX SHA256、源 checkpoint SHA256、协议哈希、六类顺序、输入形状和输出形状；任一不匹配都不允许推理。
- PyInstaller 目录包不要使用 `collect_all("onnxruntime")`，它会把量化、Transformer 等不相关工具模块全部打入。只收集 ONNX Runtime 必要 DLL 和推理模块。
- 便携模式需要 `portable.flag`，数据根目录才会放在 EXE 旁的 `data`；否则会写入 `%LOCALAPPDATA%`，导致用户备份整个文件夹时丢掉玩家档案和布局。
- 隔离验收不能只在原目录启动：要复制到另一绝对路径，从那里启动，确认状态中的模型路径指向包内部，并在重启后读回布局。
- 模型的主指标更高不等于游戏控制更成熟。完整 A/B 中 OpenMMLab COCO17 的 3-seed mean macro-F1 为 0.8118，Penn Core13 为 0.7996，但困难负样本误触分别为 45.45% 和 15.91%。对实时游戏输入，误触成本很高；因此 Penn Core13 保持研究默认，OpenMMLab COCO17 seed42 仅作为已授权的内部链路实测模型。
- Core13 不能从 COCO17 输入硬裁剪。它的冻结预处理是 MediaPipe33 world landmarks 三轴 One Euro(0.10,80,1.0)，逐帧髋中心归零，再用 24 帧肩髋距离中位数缩放；Root Motion 另用图像坐标髋中心。只有按这条链路才与 Penn 训练协议一致。

## 2026-08-13：原生取景承载层不能设为不可见

Camera2（安卓原生相机接口）把 `TextureView`（相机画面承载层）的 `SurfaceTexture`（图像缓冲表面）作为捕获会话输出时，不能为了隐藏底层预览而把它设为 `INVISIBLE`。荣耀 ELI-AN00 会因此一直等不到可用表面，表现为镜头探测完成但取景不启动、“开始识别”看似不可用。正确做法是让承载层保持 `VISIBLE`，再在其上方用原生 `ImageView`（图像显示控件）显示同一 YUV 帧旋转后的简易取景画面；识别仍直接消费 YUV 数据，不经网页逐帧传图。停止、切角色和异常路径必须同时关闭捕获并清空取景图。

## 2026-08-13：单台样机验收不能演变为设备专用实现

当前连接手机只用于暴露和复现真实问题。修复必须依据 Camera2（安卓原生相机接口）的运行时能力、传感器方向、屏幕方向、镜头朝向、实际输出尺寸组合和真实收帧结果，禁止按品牌、型号、相机编号或焦距写特判。独立设备不得依赖当前样机生成的缓存；清空数据后的冷启动必须能够重新探测并安全回退。当前样机通过只能证明该样机通过，不能冒充全安卓兼容。玩家身体校准属于通用产品功能，应按玩家档案累积多次和跨天记录，与设备硬编码严格区分。

## 2026-08-13：便携包附带驱动也不能静默安装

ViGEmBus（虚拟手柄驱动）安装器只能来自 Nefarius 官方发布页，并在封包前同时核验 SHA256 与 Authenticode（Windows数字签名）。程序启动只检测 `ViGEmBus` 内核服务和手柄连接状态；未安装时由本机用户点击后才通过 `ShellExecuteW` 的 `runas`（管理员授权）动作启动未修改的官方安装器。安装接口必须限制为回环地址，已就绪时不得启动安装器，校验失败必须拒绝执行。不能用测试需要为由卸载本机现有驱动；未安装分支用依赖注入模拟管理员启动命令。

## 2026-08-13：低分辨率推理帧不能兼作用户预览

把 480×270 的 ImageReader（图像读取器）推理位图每三帧旋转一次，再放大到全屏 ImageView（图像显示控件），会同时造成模糊、约 10 FPS 的卡顿以及持续的 Bitmap（位图）分配/回收抖动。Camera FPS（相机取帧率）也不等于 Inference FPS（识别帧率），界面必须分别显示。正确架构是 Camera2（安卓原生相机接口）将 720p 等设备实际支持的预览尺寸直接输出到 TextureView（GPU取景表面），并用 Matrix（变换矩阵）统一处理传感器方向、屏幕方向、裁剪与仅前置镜像；独立低分辨率 YUV Surface（图像输出表面）仅供模型推理。双 Surface 组合必须在每台设备运行时建立会话实测，失败时记录技术日志并回退安全单流，不能写死品牌、型号、镜头编号、焦距、方向或分辨率。

## 2026-08-13：Camera2 取景显示不要重复手写方向与缩放

手写 TextureView（纹理取景控件）的布局尺寸交换、View 旋转、镜像缩放和 Camera2（安卓原生相机接口）缓冲方向，会在设备自然方向、屏幕旋转、宽高比或前后摄变化时发生重复旋转、错轴或拉伸。预览改用 AndroidX Camera Viewfinder 1.6.1（安卓官方取景组件）：Camera2TransformationInfo（相机变换信息生成器）直接读取 CameraCharacteristics（镜头特征），ViewfinderView 使用 EMBEDDED（内嵌纹理模式）和 FILL_CENTER（保持比例居中填充）。相机发现、物理镜头、双 Surface（图像输出表面）和独立低分辨率推理链保持不变。该稳定版要求 compileSdk 36、Android Gradle Plugin 8.9.1 和 JDK 21，但 minSdk 仍为24，不因此提高最低可安装安卓版本。

## 2026-08-13：预览 FPS 不能证明 MediaPipe 33 点有效

Viewfinder（取景组件）清晰且 Camera2（安卓原生相机接口）达到 30 FPS，只能证明预览 Surface（图像输出表面）工作；ImageReader（图像读取器）、YUV 转 Bitmap（位图）、`detectForVideo`（同步视频人体推理）、PoseResult（人体结果）、WebSocket（网络关键点帧）和电脑接收仍可能分别中断。运行诊断必须同时保留读取帧数、提交推理数、detect 调用/异常数、推理位图尺寸与方向、`pose_count`、最低全身可见度、原始/编码首点、手机发送和电脑接收累计数。MediaPipe 已通过 `ImageProcessingOptions.rotationDegrees`（图像方向参数）把结果转到正向坐标后，不得在编码时二次旋转。人体分析默认选择设备实际支持且接近 640×360 的等比例尺寸，弱机回退接近 480×270；持续无人时只短时切到不高于约 960×540 的重定位档，发现人体后回到平衡档。运行预览采用 FIT_CENTER（完整显示）以免用户看到的身体范围与模型实际完整取景范围产生误导。
## 2026-08-21：原生 Pose 输入必须统一裁剪、步长、方向和时间轴

Camera2 的 YUV_420_888（安卓相机 YUV 图像格式）不能按紧密排列的 NV12/NV21（常见 YUV 打包格式）读取：每个平面都必须使用自身的 cropRect（有效裁剪区）、rowStride（行步长）和 pixelStride（像素步长），否则不同设备会出现拉伸、偏移或颜色异常。MediaPipe PoseLandmarker 的 `ImageProcessingOptions.rotationDegrees` 已负责把输入转为正向坐标，关键点编码端不能再次旋转；发送的 width/height 也应对应实际推理位图的正向尺寸。VIDEO（视频）模式的时间戳应优先来自相机帧自身的单调时间，并在丢帧/高帧率下强制递增。实时控制不额外做时域平滑，避免延迟或掩盖输入方向/画幅问题。
## 2026-08-21：原生相机链收敛到 CameraX

自写 Camera2 双 Surface、物理镜头扫描、Viewfinder 承载层和 YUV_420_888（安卓相机 YUV 图像格式）转 Bitmap（位图）细节在当前样机上长期难以证明 Pose33（33点人体关键点）输入可靠。基础链改用 CameraX（安卓官方相机封装）的 Preview（预览）+ ImageAnalysis（图像分析）共享生命周期：PreviewView（官方预览控件）负责显示变换，ImageProxy（分析帧）直接交给 MediaImageBuilder（MediaPipe 官方图像构造器），rotationDegrees（旋转角度）只使用 ImageProxy.imageInfo 提供的一次。只枚举可绑定的通用前置/后置选择器；超广角和物理镜头以后在基础真人链稳定后再恢复。
## 2026-08-21：摄像头识别路径再次回到 WebView

CameraX/Camera2 原生识别在当前样机上未能证明人体关键点稳定，因此正式路径改回历史上已使用的 WebView（网页视图）`getUserMedia`（网页媒体采集）+ MediaPipe Tasks Vision（网页姿态模型）。视频预览、骨架画布与前置镜像共用同一显示变换；每一帧只允许一次 VIDEO（视频模式）推理，并以视频时间或单调时间戳发送 `pose_frame_v2`（姿态帧协议）。NativeAudio（原生 Vosk 离线语音）和 SensorBridge（手持传感器）保持独立，手持角色不初始化摄像头或姿态模型。

## 2026-08-21：WebView 固定 Full 模型与单一前置镜像

为避免“摄像头帧率”和“模型是否启动”混淆，摄像头角色固定使用随包的 `pose_landmarker_full.task`，运行前必须完成 FilesetResolver（模型运行时资源解析器）和 PoseLandmarker（姿态识别器）初始化；`window.__motionDebug` 只提供开发诊断，不堆到正式界面。前置画面、骨架和遮罩放在同一 `cameraStage`（取景容器）上，仅容器执行一次水平镜像，发送关键点仍保持未镜像坐标。

## 2026-08-21：Android 构建基线固定为 JDK 21

Android 工程现在以 JDK 21 LTS（长期支持版）作为统一构建基线，`@capacitor/app`（Capacitor 官方应用生命周期插件）的 backButton（系统返回键）实现随 `npx cap sync android` 正常纳入 APK。同步后的 Java source/target compatibility（源码/目标兼容级别）必须保持 21；不要再用旧的 Java 17 修复脚本覆盖生成的 Gradle 配置。
